# Benchmark DHOLE

Запуск из корня репозитория в Linux/WSL с установленным окружением DHOLE:

```bash
bash benchmark/run.sh             # N=10 запусков, M=10 CDS, seed=1
bash benchmark/run.sh 20 15 42     # N M seed
```

Нужны `test/MG1655.fna`, `test/MG1655.gff`, Bash, tar и пакет ggplot2
в окружении `oligo_design`. Используется `tools/run-r`; зависимости автоматически
не устанавливаются. Синтетические pTarget/pCas совпадают с `test/test_run.sh`.

Каждый запуск получает M различных случайных CDS из GFF (locus_tag, иначе gene).
Между запусками CDS могут повторяться. Seed и выбранные CDS сохраняются.
DHOLE запускается отдельным процессом, последовательно, с `--filtering-level 2`;
остальные параметры дизайна остаются дефолтными, включая число потоков.
Ограничения размеров плеч из интеграционного теста не применяются.

Результаты создаются в `benchmark/results-ДАТА-ВРЕМЯ-PID/`:

- `analysis.pdf`: ggplot-графики времени (boxplot, отдельные точки, средние),
  процентов успешных/неуспешных дизайнов, гистограммы Tm и GC,
  barplot категорий фильтрации кандидатов, причин отбраковки и стадий ошибок.
- `timings.tsv`, `mean_times.tsv`: время каждого запуска и арифметические средние.
  Real — время всего процесса DHOLE, CPU — user + system, включая ожидаемые
  дочерние процессы. Инициализация и построение индексов входят в измерение;
  выбор CDS, анализ и архивирование не входят. Неуспешные запуски учитываются.
- `targets.tsv`, `success_rates.tsv`: успех — `status=ok` в design_summary.tsv;
  отсутствие строки тоже считается неуспехом. Знаменатель — все N×M попыток.
  Код возврата процесса сохраняется отдельно: нулевой код не означает успех CDS.
- `primers.tsv`: шесть финальных PCR-праймеров каждого успешного дизайна.
  Tm берётся из WetLab-отчёта DHOLE (округление до 0.1 °C), GC вычисляется
  по последовательности отжига без сервисных хвостов. sgRNA-олигонуклеотиды
  не включаются. Повторные CDS учитываются как отдельные попытки.
- `rankings.tsv`, `filter_counts.tsv`, `rejection_counts.tsv`: все доступные
  строки кандидатов, включая неуспешные мишени; стадии и попытки могут
  учитывать одну пару повторно. Неоценённые фильтры выделены отдельно;
  несколько причин отклонения могут относиться к одному кандидату.
- `sampled_cds.tsv`, `metadata.txt`: выборки, seed, контрольные суммы входов,
  версии R/пакетов; параметры DHOLE хранятся в его `run_parameters.tsv`.
- `dhole-results.tar.gz`: автоматически создаётся после анализа, содержит
  `raw/` со всеми выходами DHOLE, плазмидами, командами и логами запусков.
  Исходная папка `raw/` сохраняется; архив и PDF находятся рядом.

Если данных для графика нет, PDF содержит соответствующую пометку.
Аварийный выход DHOLE не останавливает следующие запуски. Ошибки самого
анализа/архивирования завершают benchmark с ошибкой и сохраняют исходные данные.

Проверка анализа без запуска DHOLE:

```bash
bash tools/run-r benchmark/test_analysis.R
```
